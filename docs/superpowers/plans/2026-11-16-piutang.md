# Piutang talangan (FIN-19) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Catat talangan berisi beberapa orang dengan nominal manual, terima cicilan ke dompet pilihan, dan tampilkan sisa piutang di sheet Saldo total.

**Architecture:** Tiga tabel baru (`receivables`, `receivable_debtors`, `receivable_payments`). Pembayaran = transaksi INCOME biasa berkategori bawaan "Piutang dibayar" yang ditautkan lewat `receivable_payments`, jadi saldo/laporan tidak butuh logika baru. Modul backend baru `receivables`; dashboard tambah `receivableRemaining`. Mobile: fitur baru `features/receivable` + baris di sheet Saldo total.

**Tech Stack:** Fastify 5 + Zod + Prisma 6 (PostgreSQL 16), vitest; Flutter 3 (Riverpod generator, freezed, go_router).

**Spec:** `docs/superpowers/specs/2026-11-16-piutang-design.md`

## Global Constraints

- Tanpa dependency baru.
- `schema.prisma`: hanya tambah 3 model di atas + relasi balik (`User.receivables`, `Transaction.receivablePayment ReceivablePayment?`). Satu migrasi `<ts>_receivables`, harus jalan di DB kosong.
- `openapi.yaml`: tambah `/receivables*`, schema `Receivable`, `dashboard.receivableRemaining`.
- Semua query difilter `userId`; milik user lain → 404 di URL, 400 di body (D-27).
- Nominal BigInt Rupiah 1..999.999.999, JSON integer. `date` `YYYY-MM-DD`; `occurredAt` ISO UTC.
- Kategori bawaan: `{ name: 'Piutang dibayar', type: 'INCOME', icon: 'handshake_rounded', color: '#64748B' }` lewat `upsert` `userId_name_type` (pola `FEE_CATEGORY`, D-56). Pastikan `handshake_rounded` ada di `mobile/lib/core/icons.dart`.
- Catatan transaksi pembayaran: `Bayar <nama> · <judul>` (dipotong ke 1000 karakter).
- Copy persis: `Piutang`, `Belum lunas`, `Semua`, `Catat piutang`, `Belum ada piutang`, `Bayar`, `Lunas`, `Sisa Rp…`, `Melebihi sisa utang Rp…`, `Nominal tidak boleh kurang dari yang sudah dibayar`.
- Mobile: semua kartu `FrameCard`/`FrameBox`, warna dari tema (`ink` untuk progres); format lewat `core/format/`; `refreshMoney(ref)` + invalidate provider piutang setelah perubahan; form = `SingleChildScrollView` + `Column`.
- Sheet bottom yang dibuka dari luar tab memakai `useRootNavigator: true` (bug D-76 tertutup bottom nav).
- Format hanya file yang disentuh; balikin churn line ending hasil build_runner. Tidak ada commit sampai owner minta.

## Review Focus

1. Dua pembayaran bersamaan untuk orang yang sama melebihi sisa → hanya satu berhasil → test Task 2 (cek sisa di dalam `$transaction` dengan `SELECT … FOR UPDATE` baris debtor).
2. Transaksi pembayaran dihapus dari layar transaksi biasa → sisa orang naik lagi → test Task 2.
3. `walletId` dompet arsip / milik user lain di body → 400; debtor milik user lain di URL → 404 → test Task 2.
4. Hapus talangan yang sudah ada pembayaran → transaksi pemasukan tetap, saldo tidak berubah → test Task 1.
5. Form dengan baris orang kosong/nominal 0, atau 21 orang → ditolak dengan pesan per baris → test Task 1 (backend) + Task 4 (mobile).
